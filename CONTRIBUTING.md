## Подготовка и сборка

Нужен Mac с macOS 14+ и Xcode либо Swift 6 с macOS SDK. Проект использует системные SwiftUI, AppKit и Swift Charts; сторонних пакетов в `Package.swift` нет. Откройте корневой `Package.swift` в Xcode или работайте из терминала:

```sh
bash scripts/swift.sh build
bash scripts/swift.sh test
bash scripts/build-app.sh
```

Обёртка `scripts/swift.sh` направляет сборку, кэши и временные файлы в игнорируемую папку `temp/`. Собранное приложение и zip находятся в `temp/outputs/`. Старые `.build`, `outputs` и `work` тоже исключены из Git; перемещённые кэши компилятора не переиспользуйте, так как они могут содержать абсолютные пути.

Скрипт сборки создаёт приложение для архитектуры текущего Mac, копирует ресурсы переводов и текст MIT в `Sumbar.app/Contents/Resources/`. По умолчанию применяется подпись ad hoc для локального использования. При наличии Developer ID Application можно указать свою действительную идентичность:

```sh
SUMBAR_SIGN_IDENTITY='Developer ID Application: Your Name (TEAMID)' bash scripts/build-app.sh
```

Эта команда подписывает приложение, но не выполняет нотариализацию. Для публичного выпуска остаются подпись, нотариализация и ручная проверка доступности. Ключи, сертификаты, пароли и загруженные котировки не включайте в репозиторий.

## DMG и универсальная сборка

Для установочного образа нужны Python 3.11+ и инструменты из `packaging/requirements.txt`. Они используются только при упаковке и не входят в приложение:

```sh
python3 -m venv temp/distribution-venv
temp/distribution-venv/bin/python -m pip install -r packaging/requirements.txt
SUMBAR_UNIVERSAL=1 bash scripts/build-dmg.sh
temp/distribution-venv/bin/python scripts/check-distribution.py --universal
```

В `temp/outputs/` появятся `Sumbar.dmg`, `Sumbar-macOS.zip` и `SHA256SUMS`. `SUMBAR_UNIVERSAL=1` включает arm64 и x86_64; без переменной локальная сборка остаётся для текущего Mac. Положение значков, фон и ссылка в `/Applications` задаются файлом `packaging/dmg-settings.py`; оформление записывается без автоматизации Finder. Проверка монтирует DMG только для чтения и сравнивает приложение с ZIP, проверяет обе архитектуры, минимальную macOS, подпись, MIT, переводы и раскладку окна.

Не меняйте FinderInfo подписанного `.app` после подписи: это нарушает строгую проверку подписи. Настройки внешнего вида установщика должны оставаться на уровне образа и его `.DS_Store`.

## Сайт документации и публикация

[Сайт](https://ahrik.github.io/sumbar/) — статические страницы GitHub Pages. Навигация, стили и поиск работают без внешних шрифтов, аналитики и серверного приложения. Основные тексты собираются из существующих Markdown-файлов; `web/index.md` задаёт главную страницу.

```sh
temp/distribution-venv/bin/python -m pip install -r web/requirements.txt
temp/distribution-venv/bin/python scripts/build-docs.py
temp/distribution-venv/bin/python scripts/check-docs.py
python3 -m http.server 8767 --directory temp/site
```

Автоматизация `.github/workflows/docs.yml` проверяет и публикует сайт при обновлении `main` или ручном запуске. В настройках Pages выбран источник GitHub Actions; правило окружения разрешает публикацию только из `main`.

Публикация тега `v<версия из Info.plist>` запускает `.github/workflows/release.yml`: release-тесты, универсальная сборка, DMG и проверка файлов. После успешных проверок создаётся черновик GitHub Release со всеми файлами, затем он становится публичным. Имена файлов сохраняются, поэтому адрес `/releases/latest/download/Sumbar.dmg` ведёт на последнюю опубликованную версию. Подпись ad hoc в этой схеме не заменяет Developer ID и нотариализацию.

Логотипы SVG хранятся в `branding/`, нативный знак — в `Sources/Sumbar/Resources/SumbarMark.pdf`. Их общий мастер — `scripts/brand-assets.swift`; после изменения геометрии запустите его и сохраните результаты в Git. Подробности и варианты фона — в [руководстве по логотипу](docs/BRANDING.md).

| Область | Файлы |

| Запуск, строка меню, панель и окно | `App.swift`, `DesktopControls.swift`, `PanelView.swift` |
| Состояние, настройки и локализация | `Store.swift`, `Preferences.swift`, `Localization.swift`, `Resources/` |

Пути в таблице указаны относительно `Sources/Sumbar/`. Проверки находятся в `Tests/SumbarTests/`.

## Проверки

Обычные тесты используют синтетические ответы; они не запрашивают системное разрешение уведомлений и не отправляют настоящие уведомления. Для изменений приложения выполните обычные тесты и сборку release. Изменения запуска или оркестрации загрузок проверяйте в release: тест одного поставщика не покрывает полный запуск.

```sh
bash scripts/swift.sh test
bash scripts/swift.sh test -c release
bash scripts/build-app.sh
python3 scripts/check-launch.py temp/outputs/Sumbar.app --seconds 30
```

Последняя команда требует рабочего стола macOS. Она запускает настоящую release-программу обычным способом, с `--preview` и с `--preview --pin-panel`, проверяет размеры видимой панели и устойчивость процессов, затем завершает только свои дочерние процессы.

Для осознанной проверки реальных сетевых источников:

```sh
SUMBAR_LIVE_TESTS=1 bash scripts/swift.sh test -c release
```

Проверяются ЦБ, Finmind и банковские источники: три прямых банка и Bank.uz, включая полный старт и повторное обновление. Доступность внешнего сайта может влиять на результат. Загруженные ответы храните в `temp/work/`, вне Git. Для банковских фикстур доступна переменная `SUMBAR_BANK_FIXTURES`; подробности — в [BANK_SOURCES.md](BANK_SOURCES.md).

После правок только документации проверьте относительные ссылки, примеры команд и соответствие описаний коду. Полная проверка приложения нужна, когда меняется его сборка или поведение.

## Правила изменений

- Отделяйте разбор ответов источников от SwiftUI. Для денег сохраняйте Decimal, номиналы и направления покупки/продажи.
- Не заменяйте неизвестные значения нулями, исторический курс сегодняшним или отсутствующий банковский канал другим каналом.
- Различайте дату источника и успешную локальную проверку. Сохраняйте ограничения актуальности, отмену и `Retry-After`.
- При изменении схемы источника добавляйте содержательные синтетические проверки. Для форматов сохранения проверяйте старые данные и ошибки чтения/записи.
- Обновляйте обе локализации и документацию затронутого поведения. Банковские имена, тикеры и исходные диагностики сохраняют собственный текст.
- Делайте небольшие изменения с описанием видимого результата и выполненных проверок. Сохраняйте уведомление об авторских правах и MIT при распространении.

Состояние уведомления записывается до доставки. Повреждённые файлы правил и архивов сохраняются, а ошибка чтения не должна приводить к молчаливой перезаписи. Общие снимки ЦБ переиспользуются между валютами; запросы одной даты объединяются, диапазоны загружаются последовательно, отмена прекращает новые запросы после текущего общего запроса. Недельные выборки и разрывы графика не должны создавать вымышленные цены.

Действующие правила данных описаны в [DATA_SOURCES.md](docs/DATA_SOURCES.md). MIT распространяется на код и документацию; включать чужую рыночную базу в исправление или релиз без соответствующих прав нельзя.

## Сообщения об ошибках и предложения

Сообщения об ошибках и предложения принимаются в [GitHub Issues](https://github.com/ahrik/sumbar/issues). Укажите версию программы и macOS, архитектуру Mac, шаги воспроизведения, ожидаемый результат, фактическое поведение и сообщение об ошибке. Для курсов добавьте название источника, валюту, операцию, способ обмена и показанные даты. При необходимости приложите обезличенный снимок экрана.

Не публикуйте целиком личные `alerts.json`, `cache.json` и другие рабочие файлы, ключи подписи или реальные загруженные страницы. Достаточно минимального синтетического примера. Предложения удобно описывать через задачу пользователя и ожидаемое поведение.

Дальнейшие приоритеты — в [исследовании и плане развития](COMPETITOR_RESEARCH.md). В числе открытых направлений: дополнительные прямые банки, позиции, резервное копирование пользовательских данных и подтверждённые события выплат. Это направления разработки без обещания сроков.
